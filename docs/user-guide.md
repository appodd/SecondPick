# Windows 用户指南

## 安装和启动

在 Windows 10/11 的 PowerShell 中按[首页](../README.md)安装。前端构建产物已随源码提供。需要重建时执行 `npm --prefix web ci` 和 `npm --prefix web run build`。

运行 `shopping-agent-web` 后访问 `http://127.0.0.1:8765`。默认使用 `config/default.toml` 和本机的 `data/settings.json`，浏览器登录资料默认位于 `data/browser-profile/`。已有安装应沿用原配置和数据目录，不要为了升级删除数据库。

基础安装使用 `python -m pip install -e .`，无需 Codex CLI 或视觉扩展即可启动工作台。准备闲鱼登录前运行 `python -m playwright install chromium`，真实采集还需下述独立引擎环境。需要视觉分析时再安装 `python -m pip install -e ".[vision]"` 并配置模型；仅需商品图片缓存的解码校验时可单独安装 `python -m pip install "Pillow>=10.0.0"`，不需要视觉模型。

## 首次配置

全新数据目录没有选购项目或商品。先在使用引导选择使用模式，再检查运行环境，完成后进入选购项目创建：

- **基础模式**：应用基础、采集引擎环境和闲鱼连接检查通过，即可点击“完成基础配置并开始使用”，无需配置 Codex CLI。
- **AI 增强模式**：在基础配置上额外检查 Codex CLI 和账号授权，再点击“完成 AI 增强配置并开始使用”。自动研究仍按项目另行授权，默认不授权。

视觉模型始终可选，未配置或验证失败均不阻止完成引导。之后可以从设置重新进入引导切换模式。模式选择不会启动采集、调用模型或改动已有项目的研究授权。尚未配置好必需服务时，已有数据仍可浏览，可用操作以界面状态为准。

点击“打开闲鱼登录窗口”，在弹出的网页中手动完成登录。**保持浏览器打开，返回应用验证连接，验证完成后再关闭浏览器。** 登录操作由用户完成，不要分享 Cookie 或登录文件。

AI 研究需要本机可用的 Codex CLI；可以用 `codex login status` 检查认证。模型费用与可用性取决于自行配置的服务。视觉模型是可选项。

采集引擎检查会提示是否缺少独立运行环境。管理员可阅读并运行 `scripts/setup_monitor.py` 准备依赖，再检查配置路径；默认引擎关闭，配置变更需重新启动服务。不要同时启动两个实例使用同一运行数据。

### 准备独立采集环境

以下用于首次准备当前代码支持的监控环境。应用元数据要求 Python 3.9+，但独立引擎安装脚本要求 **3.11+**；建议使用 Windows Python **3.12**，以匹配仓库提供的锁定依赖。还需安装系统 Chrome，并通过本地浏览器探测。

如果已存在引擎目录、本地配置或正在运行的服务，先核对版本、路径和数据；不要重复克隆、覆盖配置或同时启动第二个实例。

```powershell
# 在项目根目录执行；引擎目录尚不存在时才克隆。
git clone https://github.com/Usagi-org/ai-goofish-monitor.git data/research/ai-goofish-monitor
git -C data/research/ai-goofish-monitor checkout f85d140b6b45029d9a0925feb96dad733b41396d

python scripts/setup_monitor.py
```

版本以当前 `src/shopping_agent/monitor_engine.py` 中的 `SUPPORTED_REVISION` 为准，不随意替换为引擎最新分支。安装脚本准备 `.monitor-venv` 并检查环境；失败时先修复检查项，不跳过兼容性检查。

检查通过后，脚本会在文件不存在时生成 `config/monitor.local.toml`。核对其中的数据库、引擎和解释器路径；原默认服务若正在运行，应先正常停止，再使用这个本地配置启动：

```powershell
shopping-agent-web --config config/monitor.local.toml
```

默认的 `shopping-agent-web` 仍读取 `config/default.toml`，不会自动切换配置。安装脚本也不会自动开始真实采集；启动后仍需验证闲鱼登录，在界面核对和确认任务范围。已有安装应沿用自己的原配置，而不是用上述默认路径替换业务数据。

## 新建选购项目

完成所需配置后点击“新建选购项目”，手动填写想买什么、预算、必须条件和个人偏好，或让 AI 整理后核对，再确认创建。不会自动导入仓库测试数据。

## 只抓取的使用方式

可以只使用监控采集和商品管理，按以下步骤操作：

1. 准备应用基础环境、独立采集引擎及闲鱼登录，并在设置中验证连接。
2. 点击“新建选购项目”，手动填写项目名称和目标等必要字段，不点击 AI 整理。
3. 不勾选“授权自动批次研究”，确认需求后进入监控配置，手动填写关键词和采集范围，不使用 AI 生成监控草案。
4. 预览并确认范围，再按需启动单次采集或持续监控。在“全部商品”浏览、搜索、筛选和收藏。

首次引导选择“基础模式”，基础环境、采集引擎和闲鱼连接检查通过即可正常完成配置。无需为了只采集而配置 CLI 或提前退出引导；启动采集前仍需预览并确认监控范围。

自动研究未授权、也未发起手动 AI 请求时，不会为了分析商品调用模型。AI 整理、研究或追问需要另行准备 Codex CLI 及认证。只采集不会产生 AI 研究报告；需要分析时可以再启用相应能力。

## 采集和研究

### 持续监控：按计划收集商品

创建监控时核对关键词、页数、数量与运行范围。监控采用一次明确范围确认，原范围内定时运行及暂停／恢复不重复确认；改变范围须重新确认。持续监控开关表示是否允许调度，当前采集是否执行应看运行状态。单次采集完成后若要再采一轮，需要重新确认范围。

持续监控在本机服务运行、采集环境和登录状态可用、计划允许时分轮执行。开启后也可能处于等待下一轮，不能把开关打开理解为一直在抓取。可以在“监控任务”查看调度状态、实际执行记录及异常；采集结果保存在“全部商品”。

默认配置对搜索尝试设置至少 1800 秒间隔。遇到验证码、访问限制、登录失效应停止并按正常流程处理，不绕过验证。禁止向平台发消息、操作平台收藏、议价、下单或支付；工作台本地收藏仍可使用，应用不会替用户完成交易。

监控中的“允许采集公开卖家主页与发布记录”默认关闭；明确勾选并确认后，采集引擎才会额外访问卖家主页及其商品／评价列表。未开启时仍可保留商品详情响应已有的卖家字段。该采集选项不等于 Agent 已能自动执行卖家主页调查，也不代表卖家信息已独立核实。

### Agent 研究：结合目标核对已有证据

采集到的商品不保证完全满足目标。Agent 在已保存的商品证据基础上，按预算、必须条件和个人偏好深入分析，形成候选判断、理由及待核实问题。它不会因为商品出现在搜索结果中就认定商品符合要求，也不能把卖家描述当作独立核验。

研究有两种发起方式：

- **自动研究**：项目已授权自动研究、研究调度未暂停，且 AI 驱动与可用队列等条件满足时，系统可以安排后续研究。是否有新任务以及处理了哪些商品，以“Agent 研究”的研究安排和任务记录为准。
- **手动研究与追问**：在“Agent 研究”发起任务，或围绕选中的商品、已有报告提出具体问题。临时研究指令用于本次任务；修改长期选购要求应从研究概览的目标调整入口操作。

### 分别查看开关、执行状态和覆盖范围

监控与研究分别控制：暂停监控不等于暂停研究，暂停研究也不等于暂停监控。商品已入库、已安排研究、已逐项分析和已进入报告是不同状态，不能把商品总数视为 AI 已分析数量。

查看结论时，核对任务状态、目标版本、实际输入的商品与覆盖范围。某次有限批次研究的结果，不代表项目内所有商品都已评估。报告引用旧目标或较早证据时，也需要重新核对。

### 遇到失败或条件不满足

- 登录失效或平台验证：先停止相关采集，在设置中按正常流程登录并验证连接，再检查原任务能否恢复。
- AI 驱动不可用、研究失败或中断：检查设置和失败记录，确认哪些任务实际完成，再决定是否重新发起。已有商品不因此变成已研究。
- 暂无可安排的研究任务：核对授权、暂停状态和覆盖范围；研究空闲不代表所有剩余商品都已符合要求或失去研究价值。

## 调整目标

从研究概览的当前目标进入调整面板。说明修改意图，核对 AI 草案中的变化及保留条件，预览影响后再确认保存。AI 整理不等于已保存。

历史商品、收藏和研究记录保留。旧报告仍基于当时目标，需要重新核对；监控搜索范围不会自动修改，应检查现有关键词是否覆盖新目标。改买另一类商品或想并行比较两套目标时，建议新建选购项目。

## 视觉配置与图片审批

安装视觉扩展后，可在设置中添加模型、保存密钥、选择当前配置并验证连接。连接验证及启用时的验证须明确确认，会向所选服务发送内置测试图，可能产生费用；验证通过不代表已分析商品图片。

商品图片缓存、视觉模型配置、图片范围审批和实际执行分别控制。准备图片只获取获准图片，不授权模型分析。图片分析的审批绑定具体商品、目标版本、图片、模型、用途及费用确认；保存配置或确认范围本身不会执行分析。默认 `shopping-agent-web` 启动的服务未开放项目图片分析执行，当前没有文档化的生产启用命令，不能通过完成视觉设置视为已就绪。已有图片观察仍可按实际状态查看；AI 图片观察不等于独立核验。

## 数据与故障

模型调用可能发送目标、商品文字证据，以及明确获准的图片。详见[隐私说明](PRIVACY.md)。不要将运行目录、登录资料、数据库或真实截图提交到 Git。

接口不可用时先检查服务、端口和配置；请保留数据库，不要用测试数据库覆盖已有数据。研究失败或被中断不代表已经完成，界面有结果和历史时也需核对其目标版本与覆盖范围。
